- KOS-MOTION-004 PR-04, the runtime driver and the engine hooks (Tasks: KOS-MOTION-004): `src/kritva_motion/runtime/driver.py` (`Driver(engine, coordinator, backend)`, the only place where the engine, the stores and a backend meet; no clock, no thread, no I/O) executes the requests that engine calls return after checking each against the backend's current declaration (contract 17.3: target type, mode, joint type, position hold, controlled stop or cancellation, declared concurrency); a refused request is never sent and the engine is told (a dispatch or hold ends FAILED(BACKEND_REJECTED_DISPATCH) with the undeclared capability in the record detail, interpretation I-41). `poll(now_ms)` applies the backend's reports in order, each once, then the engine `tick`; a report for an unknown reference, for another target, or not well formed is ignored and logged; request accepted is never confirmation, a confirmation must be bound to reference and target, and an unconfirmed termination is decided by the engine's bound (17.5); an exception from the port or an answer of the wrong shape is a loss of the backend. Engine hooks (BACKEND.md section 8): `execution_rejected`, `update_backend_description` and the read-only `joint_type`; finding F-8 is closed: the engine now emits `BACKEND_HEALTH_CHANGED` and `FEEDBACK_STATUS_CHANGED`. The port gains the optional `target` of `request_termination` (I-44); the simulator can script a hold start and echoes the movement's reference on `release_hold`. CT-BE-02, CT-BE-04 and CT-BE-07 move to IN_SCOPE with one dedicated test each (117 IN_SCOPE, 5 DEFERRED, 2 OUT_OF_SCOPE: CT-BE-03 and CT-BE-06 are PR-05); one earlier assertion that counted every event of a tick ignores the new event, the other 112 earlier tests pass unchanged. The tests were checked with four deliberate faults (no capability check, no target binding, an accepted request treated as confirmation, a release failure not applied), each caught. Software evidence only: simulated backend, no actuator, no transport.
